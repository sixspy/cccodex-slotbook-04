# 候补晋升同册判定（2026-11-21 当日锁死）

> 本文件是晋升写路径的唯一判定来源。改动晋升相关代码前先读本页；偏离即视为
> 「晋升同册偏航」，必须记录并拒绝写入。

## 选定的正确性路径：甲

**甲路径：持档锁同事务晋升。**

1. 先抢档期锁 `slot:<code>`；
2. 在**同一连接、同一事务**内完成两笔业务写：
   - 插入占位行（`holds`，带 `wait_id` 来源）；
   - 把候补行改为 `已晋升`；
3. 任一笔失败，两笔一起回滚，占位与候补态零增；
4. 成功后写一笔 `waitlist_promote` 审计，然后释放档锁。

乙路径（先写晋升草稿、再原子落占位与已晋升）**不采用**。甲、乙不得混用；
代码里不得出现晋升草稿/影子表，也不得出现第二套晋升落库方式。

## 硬性约束

- 两人同时晋同一候补：必须抢同一把档锁；后到者只留争用痕（`contention_log`），
  不写业务。
- 一候补只进一占位：`holds.wait_id` 上有部分唯一索引兜底。
- 断言五处同态：候补态、占位行、余席、对账、审计。对账接口会输出
  `promoted_waits`、`promotion_holds`、`dual_state`、`free_seats`、
  `promotion_ok`、`audit_ok`。
- 禁止只在前端防连点；后端必须自己挡住重复晋升与并发晋升。
- 夹具与测试跑本机文件库（`tmp_path` 下的真实 SQLite 文件），不用 `:memory:`。

## 判定顺序（测试先行，已执行）

1. 造「晋升后候补仍排队」假绿夹具；
2. 落双态并存失败测，见红；
3. 落双人同晋争用失败测，见红；
4. 双红之后才允许改候补服务、占位服务、档锁与对账服务；
5. 修完跑全量，一候补只进一占位。

测试入口：`tests/test_promote_atomic.py`。

## 偏航处理

`waitlist_svc.guard_same_ledger_path` 会在每次晋升前检查：

- 约定的路径标识是否仍为甲；
- 库中是否出现 `promotion_drafts` / `promotion_shadow` 等草稿/影子表。

命中任一条件：写 `promotion_path_drift` 审计（detail 记录原因），返回 409，
业务零写。
